Cómo funciona Cuturl, pieza por pieza

De lo general a lo específico: el ciclo de una petición, los dos recorridos, y el código real de cada archivo con comentarios línea a línea. Para entender Laravel, no solo usarlo.

1 Panorama

¿Qué es, en una frase?

Cuturl recibe una URL larga, guarda una fila con un código corto, y cuando alguien visita ese código lo redirige al destino. Toda app Laravel es el mismo ciclo: llega una petición, pasa por capas, sale una respuesta.

    4 La idea de fondo

    Los 3 "puntos de cambio"

    La decisión más importante: aislar las 3 cosas que van a cambiar, para que añadir features sea sumar, no reescribir.

    #1 · Generar el código

    CodeGenerator (interfaz)

    Hoy: RandomCodeGenerator, código aleatorio de 6 caracteres.

    Mañana: cambiar una línea del binding para usar Sqids → códigos no enumerables.

    #2 · Validar el destino

    StoreLinkRequest

    Hoy: URL http/https bien formada, máx. 2048 caracteres.

    Mañana: regla SafeUrl (bloquear IPs internas → anti-SSRF/phishing).

    #3 · Resolver el link

    LinkController@resolve

    Hoy: busca el código y redirige con 301.

    Mañana: expiración, contraseña, interstitial y analítica.

    Por qué el esquema mínimo. La tabla links empieza con solo code y destination. Columnas como expires_at entran con su propia migración cuando se construya esa feature. Así se aprenden migraciones de verdad.

    Estado: Iteración 1 completa — crear + redirigir, en http://url-shortener.test. Siguiente: Iteración 2 (Sqids, tocando solo el binding del punto #1).
